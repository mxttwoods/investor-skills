# Decision journal

One record per decision. Process quality is evaluated separately from outcome: a
profit can follow poor reasoning and a loss can follow a sound process. Do not
rewrite a principle because of one outcome.

## 1. Decision context

- Date decided / decided by:
- Asset + intended horizon + mandate constraints in force:
- Evidence available at decision time (with as-of dates and source IDs):
- Frameworks and principle IDs used (e.g. `marks-risk-and-uncertainty/MRK-01`):

## 2. Thesis at decision time

- Core thesis (2–3 sentences):
- Key assumptions:
- Alternatives considered:
- Unresolved questions:

## 3. Procedure trace

- Analytical steps taken, in order:
- Supporting evidence (source IDs):
- Disconfirming evidence sought and found:
- Invalidation conditions ("this thesis is wrong if…"):
- Expected operating milestones + review dates/conditions:

## 4. Proposed action + rationale

- Action (research-further / watch / deep-dive / reject-for-mandate):
- Rationale tied to mandate (not to outcome hopes):
- Position-sizing inputs, if any (method named; no guru-score voting):

## 5. Follow-up (filled at review)

- Subsequent evidence and outcomes:
- Which milestones hit / missed, and when:
- Error classification: process error / data error / attribution error / none yet:
- Proposed skill improvement (evidence, affected principle ID, expected benefit,
  evaluation cases to run):
- Previous skill version preserved at (path/commit):

## Revision rules

- A revision proposal names the evidence, the affected principle, the expected
  benefit, and the eval cases that would test it.
- Keep the prior version auditable (commit or copy before editing).
- One outcome never rewrites a principle on its own.
